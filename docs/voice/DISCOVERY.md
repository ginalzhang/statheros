# Voice discovery (prompt §3)

1. **Stack.** Electron 45 + React 19 + Vite 8 (Forge 8), TypeScript strict, npm (`npm ci`, exact pins). Main process is Node; async via promises and the `ConfigurationQueue`. Swift helper (`native/`) owns native input over NDJSON stdio. **Electron column of §2 applies.**
2. **Existing mic capture: none in TypeScript.** The camera stream is video-only (`src/renderer/probe.ts:56`). The only mic code is the deferred Swift `SpeechProbe` on `AVAudioEngine`/`SpeechAnalyzer` (`native/Sources/SteadyNative/SpeechProbe.swift:8`). The prompt forbids Apple frameworks, so the voice module creates the one capture stream in the panel renderer (`src/renderer/voice-capture.ts:20`); the native mic stays off (the helper is never sent `microphone: enabled`).
3. **Existing audio output: none.** The app never speaks (no TTS), so the only playback is the module's own earcons, which bracket themselves with `PlaybackStarted`/`PlaybackStopped`.
4. **`<<COMMAND_ENTRYPOINT>>`** = `enqueueAction(action)` → `dispatch()` (`src/main/index.ts:119`, `:122`), wrapped by `executeVoiceCommand` (`src/main/index.ts:207`). Async; resolves **after** the native ack (`supervisor.request('action')`), so this is not degraded mode. Typical duration tens of ms, worst case ≈1 s (helper round trip), so `timers.command_s` = max(30, 2 × 1) = **30**. **No abort hook** (native actions are atomic): `abort_supported = false`. No confirmations. Result text = `VOICE_LABELS[action]`. **Not LLM-backed**: it is the fixed vocabulary in `plan/PLAN.md:156` ("Steady pen down" …), parsed by `src/main/voice/steady-commands.ts`, so `dispatch_low_confidence = ptt_only`. Errors are user-facing strings (e.g. "Close Settings before pointer actions.") and surface as the ERROR toast.
5. **UI surface.** The companion panel (`src/main/index.ts:415`) is `alwaysOnTop`, `focusable: false`, visible on all Spaces and over fullscreen, so the indicator and toasts stay visible while Krita is foreground. There was no mic button (only a "Mic off" action button); the voice strip adds one. Long-press and right-click both map to `ButtonLongPress` (mute). Because the panel never takes focus, **Esc cannot reach it**: Cancel is the transcript click or the hotkey tap.
6. **Tracking.** MediaPipe in a renderer worker (`src/renderer/vision.worker.ts`), ≈30 fps, one frame in flight. Head mode exposes a face anchor but no explicit "facing screen" signal; palm mode exposes a palm anchor but no "palm raised" pose. **Assumption:** `AttentionHint`/`GestureHint` are defined and handled, but `palm_toggle` and `require_attention` stay **off and unwired** until tracking exposes those signals (palms already drive the pointer, so an unbound pose is needed first).
7. **Secrets.** No existing mechanism. `CARTESIA_API_KEY` from the environment wins; otherwise a key entered in Settings is encrypted with Electron `safeStorage` (Keychain) in `userData/cartesia-key.bin` (`src/main/voice/key-store.ts`). Main process only; never sent to a renderer.
8. **Platform.** Apple Silicon, macOS 26+, packaged `.app` via Forge (`LSUIElement`, ad-hoc signed, hardened runtime off, so no `audio-input` entitlement is required). `NSMicrophoneUsageDescription` updated (`forge.config.mjs:11`). Renderer network is blocked (`src/main/index.ts:401`); the Cartesia socket lives in main, so that block still holds for renderers.
9. **Second instance.** Possible (no single-instance lock). The voice module takes a PID lock at `userData/voice.lock` and refuses to start if a live PID holds it.

**Plan conflicts, resolved by the user's request:** `plan/PLAN.md` specified Apple `SpeechAnalyzer`, on-device recognition, and "no API key", and deferred voice to Phase 04. This implementation follows the Cartesia prompt instead (cloud STT gated behind a local wake word, with a red cloud dot). Plan rules kept: **launch microphone-off** (`plan/PLAN.md:51`; the module starts `MUTED`), the fixed vocabulary, one action per utterance, and keys/panel as the precise alternative.

**Other assumptions.** Frames are timestamped when they reach main (IPC adds about 1 ms; the same `performance.now()` clock stamps hotkeys and wakes). When inference falls behind by more than 25 frames, new frames are skipped rather than dropping the oldest: same effect, since only detection may lag and the ring buffer and forwarding never have holes.
