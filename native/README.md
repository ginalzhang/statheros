# Steady native helper

The native helper supports Steady’s working prototype, including fake input, explicitly enabled Krita input, and a bounded real-input probe. Voice input is disabled.

This Swift 6.4 package targets arm64 macOS 26.0 with the installed macOS 27.0 SDK. Electron owns and launches the executable from its packaged resources outside ASAR. It is not a separately launched service. It requires no compiler, interpreter, checkout, TCP port, or native resource directory at runtime.

Use the root `npm run build:native` and `npm run test:native` scripts. The former copies the release executable to `resources/bin/SteadyNative`. The pinned Command Line Tools currently require explicit loading of their installed Swift Testing macro plugin; the root test script records that path. SwiftPM's default build backend can compile/run Swift Testing, while its native backend builds the release executable without the sandbox-restricted dSYM operation. These are SwiftPM build backend flags, not a version or stack change.

`native/Tests/integration.py resources/bin/SteadyNative` runs process checks using `--test-fake-backend`: real stdio framing, eight-round-trip clock mapping, live-heartbeat starvation release, EOF while a fake button is held, default/emergency fake release, oversized-frame rejection, bounded-probe EOF release, idle speech counters, and deferred-voice rejection before permission/asset/capture work. Python is a development test harness only. No automated check accesses cameras/microphones, observes real desktop activation or injects desktop events.

## Runtime arguments

- No arguments: real permission, foreground and display diagnostics, fake event posting. Microphone stays off and no speech assets install automatically.
- `--test-fake-backend`: deterministic synthetic display/permissions/foreground and observable fake event diagnostics on stderr. Cannot be combined with real input.
- `--release-and-exit`: unconditional mouse-up attempt through the selected backend; default backend posts nothing. Electron passes `--real-input` when releasing after a real helper. This emergency path works before the normal packaged-identity restriction.
- `--real-input`: opt into Quartz posting. Normal real operation requires the executable to be inside `Steady.app/Contents/`; target bundle/PID and Accessibility are checked immediately before input down/move/shortcut posting. Mouse-up always attempts release.
- `--probe --real-input`: Electron-owned supervised probe. The UI must explain the operator must open a disposable Krita canvas, position the physical pointer with at least 12 logical points of clear canvas to the right, and keep Krita foreground. Electron writes `CONFIRM_DISPOSABLE_KRITA\n` after explicit operator confirmation and a switching delay. Confirmation expires after 15 seconds. The probe uses the current pointer, posts no more than a 10-point rightward stroke, tests starvation, attempts release, and exits in approximately 1.2 seconds after confirmation. It has its own independent 10 ms watchdog. Optional `--probe-rect x y width height` supplies an operator-confirmed logical Quartz canvas; otherwise a 100x100 probe rectangle around the current pointer must fit the primary display. This does not calibrate the application or validate later product drawing behavior.

## Protocol and safety

The compatibility contract is `src/shared/contracts.ts` and `fixtures/protocol-v1.json`. UTF-8 newline JSON is bounded to 16 KiB excluding newline. All timestamps are monotonic milliseconds; renderer/main clocks must be converted to native before capture submission. Hello returns protocol version, actual permission states, authoritative Quartz displays and capabilities. Native requests/replies have independent increasing safe-integer sequence numbers in one UUID session. Unexpected versions/types/actions, malformed frames, changed sessions and invalid payloads fault; expired generations, old frames and repeated commands are rejected.

The native engine launches paused and pen-up. Nonnull configured canvas is parent confirmation, not proof of calibration. Electron gates calibration, canvas confirmation, tracking readiness, and explicit real-input opt-in before normal drawing. 500 ms valid tracking is required for Resume. A capture age of 250 ms pauses/releases, checked every 10 ms independently of speech and parsing. Pings never refresh capture freshness. Foreground/PID/permission loss, display changes, EOF, signals and explicit emergency release all attempt mouse-up. EOF monitoring does not depend on stdout draining. Output sequence allocation and writing share a gate; engine locks are released before pipe writes. The watchdog sends diagnostics on a separate queue so pipe backpressure cannot stall release.

Platform metadata is collected outside the input lock on its own queue; the freshness timer, state snapshot and clock ping use the latest authoritative native snapshot. Action/configuration requests refresh metadata before taking the input lock. Native workspace activation pauses/releases directly; Quartz reconfiguration invalidates/releases before refreshing geometry. Real event posting still checks current Accessibility, foreground bundle and PID immediately before posting, and a rejected post pauses/releases without claiming a held button. Emergency release posts before metadata/engine initialization. Clock synchronization remains exactly eight round trips with a 10 ms uncertainty gate; readiness is reported separately from the first hello state.

## Deferred speech implementation

Voice input and speech-asset installation are disabled in the current prototype. The helper rejects microphone enable and speech-asset installation with `voice-deferred-phase01`; microphone disable remains allowed. The rejection code retains its historical name for protocol compatibility.

Speech recognition and diagnostic code remain in the source for future work. `ThirdParty/libfvad/` is an inactive interrupted import: `Package.swift` has no C target or dependency, so it is not compiled into the helper. The retained implementation uses Apple Speech APIs, but detector boundaries, finalization behavior, offline recognition, and speech-end-to-action timing have not been established through live hardware validation. Synthetic tests and compilation do not establish those behaviors.

Diagnostic counters use the `steady-speech-probe:` stderr prefix and contain no recognized text or audio. Electron validates the bounded schema against the current speech session. Numeric diagnostic evidence uses the historical userData path `phase01-evidence/speech-diagnostics.jsonl`, capped at 1 MiB with unchanged snapshots suppressed. Observation timestamps are not speech-end timestamps.

Historical feasibility findings and authorization records are preserved locally under `.archive/plan/` at the repository root. That directory is ignored by Git and unavailable in fresh checkouts. See the [root README](../README.md) for current capabilities and limitations.

## Canvas Accessibility observations

An anonymous workspace can be offered as `workspaceSuggestion` for explicit user review. This separate nullable rectangle does not change `availability`, `kind`, or the recognized viewport `rect`: a suggestion remains untrusted even if its structure is consistent with Krita's central workspace. It may include document tabs, rulers, or scrollbars. Electron must show a preview, permit adjustment, and require **Use canvas** before configuring it for drawing.

Suggestions require a completed scan with one unique, central, substantial direct-child `AXGroup` and its equal-bounds single-child group chain inside the window. They are not chosen by largest-area ranking, a fixed child index, or hardcoded screen coordinates. The rule uses the full internal structural rows rather than the bounded diagnostic sample. A suggestion survives a periodic rescan only for the same root/document/window signature, clears on changed root geometry or document identity, and is recomputed after a complete scan. Ambiguous or unsupported structure yields null. Explicit canvas recognition remains unchanged.

For the reviewed suggestion only, a unique measured bottom status strip can reduce its bottom edge. [Qt's Cocoa role mapping](https://raw.githubusercontent.com/qt/qtbase/5.15/src/plugins/platforms/cocoa/qcocoaaccessibility.mm) exposes `QAccessible::StatusBar` as `AXStaticText`, so that role alone is not sufficient. The strip must be a direct window child, use `AXStatusBar` or nonleaf `AXStaticText`, align with both horizontal window edges and its bottom within one logical point, and occupy no more than 20% of its height. Equal frames are deduplicated; missing or conflicting frames leave the suggestion unchanged. Cropping uses the observed strip's top, preserves the 100 × 100 minimum, and has no fixed pixel inset. An already-excluded status bar does not shrink it again. This remains a structural heuristic requiring explicit visual review; it neither identifies an exact viewport nor changes automatic detection availability. Tabs, rulers, scrollbars, or an unexposed status bar can remain in the suggestion. The earlier supplied diagnostic fixture already ended at the status bar's top, so its rectangle stays unchanged; current live layout acceptance is still required.

The helper advertises `canvas-accessibility` and emits `canvasObservation` events every approximately 500 ms after the protocol handshake. Events carry the configured generation, Krita PID, opaque window identity, current `windowBounds`, optional hashed document-title `windowToken`, a separate deep `layoutToken`, native observation timestamp, availability/reason, optional logical Quartz viewport rectangle and kind, and bounded structural `diagnostics` (or explicit null). Root window geometry is published even while viewport discovery is incomplete. A missing title produces a null document token rather than inventing a document change. The document token hashes the normalized title alone; window bounds and source identity are compared separately. The retained identity of an unchanged AX root does not switch when a WindowServer match becomes available later. An available result currently means an explicitly identified drawing **viewport**, which may include workspace around the artwork. Exact document-page boundaries are not inferred from a window or an arbitrary large group. Multiple conflicting candidates, missing permission, modal windows, or unfinished traversal report unavailable with a specific reason.

Inspection uses Accessibility plus WindowServer window metadata, on its own utility queue with 25 ms AX message timeouts and a 200 ms per-poll work budget. Attributes are read in batches; obvious toolbar/list/table/control subtrees are pruned. A search advances by up to 96 nodes per poll and retains its work between polls, bounded to 4096 inspected nodes and depth 24. Deadline exhaustion means continuing search rather than restarting the same first 200 nodes forever. After an unambiguous candidate is found, its actual element, ancestor visibility, current bounds, and parent/child membership are checked directly on later polls. Root/document changes or a changed ancestor tree discard that cache. Literal accessible canvas titles are accepted alongside explicit role/identifier matches; a generic group or scroll area remains insufficient evidence of a canvas.

WindowServer metadata is matched to a readable AX root by equal bounds. If the AX root cannot be read, fallback window bounds are provided only when there is exactly one eligible on-screen Krita window; multiple windows remain unknown rather than reusing an older focused target. This metadata API does not capture pixels or require Screen Recording permission. No permission is requested, no screenshots or window titles are saved, and the input/watchdog lock is never held for inspection. Document/window/layout metadata is hashed before leaving the helper. Unobservable document transforms still require manual reselection. The fake backend emits an explicitly unavailable synthetic observation with independent stable root geometry and layout identity for deterministic mouse-selection tests.

Document-title normalization removes the trailing Qt modification marker (`[*]`, `*`, or `•`), recognized trailing byte-size statistics such as `(12.3 MiB)`, and anchored Krita/MDI title wrappers. [Krita's `KisView::slotUpdateDocumentTitle`](https://raw.githubusercontent.com/KDE/krita/master/libs/ui/KisView.cpp) appends memory statistics and connects title updates to the memory-statistics signal, so idle refreshes can change the title without changing documents. [Qt's `QMdiSubWindow`](https://raw.githubusercontent.com/qt/qtbase/5.15/src/widgets/widgets/qmdisubwindow.cpp) can wrap that title as `Krita - [document title]`. Normalization preserves filenames, internal parentheses, literal percent signs and unsupported decorations, and a missing or empty normalized title emits a null token while retaining the known search identity. These source references establish a possible idle-invalidation mechanism, not a confirmed diagnosis of the operator's live Krita build. Unknown/localized title decorations and same-named documents may remain indistinguishable; live idle and document-switch validation is still required.

Structural diagnostics contain the inspected count, search completeness, truncation flag, metadata source, and at most 32 sampled nodes. Each node contains an indexed path such as `0/1/2`, role/subrole, a restricted technical Qt/Krita identifier or null, valid logical bounds or null, and child count. Sampling prioritizes the root and containers at least 100 × 100 points so ordinary controls do not consume the report. No accessible titles, descriptions, text values, document names, filesystem paths, or arbitrary identifiers are copied. The diagnostics object is capped to 10 KiB before the observation is serialized, preserving the 16 KiB wire bound. Missing explicit viewport identity still reports unavailable; diagnostic geometry is never treated as permission to guess a drawing region.

`restoreTarget` accepts only a bounded positive `targetPid` for the currently discovered `org.krita` process, releases input, leaves the engine paused, and asks the running application to activate. Its acknowledgment means activation was requested, not that macOS has already delivered the foreground notification. Callers must wait for refreshed foreground metadata before requiring Krita foreground again. It does not post keyboard or mouse input.

Live Krita Accessibility geometry, mouse click isolation, focus restoration, fullscreen/Spaces, and mixed-display acceptance require an operator session. Compilation and synthetic fixtures do not establish those outcomes. No live validation is performed automatically.
